# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries`、`hydropower-plant-om:meta`、
  `hydropower-plant-om:transformer-alarms` 这三项，或调用 `resetModule(模块)`。

## 主变告警口径

- **告警复位一次清干净**：复位时状态、油温/绕组温度越限标记、告警台数（`abnormal`）、
  停运残留一起回到正常口径；列表、详情面板、运营概览与导出的清单读的是同一份
  localStorage，不会再两处对不上。停运检修后复役（提交试验）同样清掉旧越限标记。
- **撤掉的告警留痕不丢失**：告警日志单独存在 `hydropower-plant-om:transformer-alarms`，
  复位只把结论从「告警中」翻成「已复位」并补复位时间与处理人；联动开出的缺陷单也只
  翻成「已消除」，记录保留在缺陷处置清单里。
- **重复复位只生效一次**：没有未复位告警痕迹的主变再点复位会被拒绝，告警台数不会减两次；
  重复发布告警也不会重复开缺陷单。
- **告警联动缺陷清单**：发布告警自动在缺陷处置里开单（等级沿用缺陷模块在册的
  一般/严重/危急，温度越限固定落「严重」），复位时同一张单翻成「已消除」；
  已经在册的缺陷结论一概不改写。
- **老数据迁移**：按原有编号（id 不动）升级，缺的字段补默认值、不拿旧值顶替已有值；
  去重按各模块第一个字段（业务编号），编号相同保留 id 最小的一条；迁移游标逐条落盘，
  取数中断后从断掉的那一条接着走；历史告警按试验日期回填，早期缺处理人的统一补录
  「系统补录」；迁移后告警日志与台账互相看齐，导入的明细同台账一致。

## 数据层验证

```bash
cd frontend
npm run verify:data
```

覆盖迁移补缺/去重/断点续传、告警发布-复位幂等、缺陷联动留痕、列表与概览口径一致、
导出与台账一致等场景。
